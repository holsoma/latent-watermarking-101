Fixes, ranked by likely gain to the four-criterion score, followed by developer-score gain:

1. **Restore word separation in the tablet hero.** In `responsive/home-768.png`, the heading reads visually as “A / signalinside / thenoise.” `responsive/report.json.frames` also records the joined text as “A signalinside thenoise.” Supply actual whitespace between the heading's text fragments and control line breaks without deleting those spaces. At 768 px, keep “A signal”, “inside the” and “noise.” as readable phrases. Recheck both visible wrapping and extracted heading text at 390, 768, 1024, 1366 and 1920 px. Likely gain: Design about 0.2 to 0.3, Usability about 0.1, Responsive Design about 0.3 to 0.5.

2. **Show the complete equation at the tablet reading width.** `responsive/study-equation-768.png` ends the formula partway through its second expression, before the variance expression visible in the 1024 and 1920 frames. The screenshot does not establish whether horizontal scrolling recovers it. Split the three expressions into separate aligned display lines at this width. If horizontal panning is retained, add a visible “Scroll equation horizontally” cue and a keyboard-accessible scrolling region. Keep the formula's readable type size. Likely gain: Usability about 0.1 to 0.2, Responsive Design about 0.2 to 0.3.

3. **Expose study section navigation below the wide-desktop breakpoint.** `responsive/study-1920.png` has a useful nine-link “On this page” list. `responsive/report.json.frames` records `localContentsVisible: false` at 768 and 1024 px, while `study/report.json` records article heights of 5,274 px on desktop and 7,463 px on phone. The phone's Contents button opens the handbook navigation in the supplied evidence. Place the existing nine section links inside a compact “On this page” disclosure near the study title on narrower screens. Retain the tested heading focus and back/forward behaviour. Likely gain: Usability about 0.1 to 0.2. This adds access to existing sections and does not change the concept.

4. **Keep the eight message bits together at 768 px.** In `responsive/home-768.png`, seven bits occupy one row and the eighth is isolated below them. Stack the controls below the dot field at that container width, or allocate an eight-column message grid with enough width for all eight controls. Preserve the order and minimum target size. Likely gain: Design about 0.1, Responsive Design about 0.1 to 0.2.

5. **Provide indexable documents if separate study search results are required.** `summary.json.transport` and `audit.txt` establish that headings, main landmarks and chapter content only arrive after JavaScript; the route reports share a home canonical and the apparent 404 remains HTTP 200. Generate a document for each actual route with its heading, main content, title, description and matching canonical in the served HTML, and serve unknown paths with HTTP 404. This has little direct effect on the four-criterion visual score, but it is the largest developer-score opportunity: Semantics/SEO could move towards 8 once those requirements are evidenced.

6. **Increase the desktop GitHub target's height.** Each route's `desktop.smallTargets[0]` records a GitHub link at 58 × 22 px. Increase its hit area to at least 24 px high, preferably with vertical padding that keeps it aligned in the header. Phone targets already pass. This is a small Responsive Design and Accessibility improvement.
